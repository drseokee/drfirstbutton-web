# 닥터첫단추 3D 환자 교육 플랫폼 — 프로젝트 핸드북

이 문서는 새 대화(새 질환 섹션 작업)를 시작할 때 Claude가 가장 먼저 읽는 기준 문서다. 여기 적힌 규칙과 절차는 지금까지 두 질환(손목터널증후군, 발목 염좌)을 만들며 확정된 것이며, 새 질환도 같은 방식으로 만든다.

## 1. 목표와 역할 분담
- 외래에서 환자에게 설명하는 EBS 명의풍 3D 교육 자료. 웹(브라우저) 기반, 질환별 5단계 스크립트.
- **모든 제작(추출·모델링·검사·뷰어·배포)은 Claude가 서버에서 헤드리스로 수행**한다. 사용자(정형외과 전문의)는 브라우저에서 결과물을 보고 의학적 피드백을 준다. 사용자 PC에는 아무것도 설치하지 않는다.
- 진행은 **한 번에 한 단계씩** 제안·확정하고 넘어간다.
- 의학적 정확성은 사용자가 최종 판단한다. Claude는 해부학 문헌 수치를 근거로 초안을 만들고, 피드백을 받으면 규칙(숫자)을 고친다.

## 2. 절차 (질환 하나 = 5 Step)
1. **스테이지 스크립트 확정** — 5단계: 외관 → 구조 노출 → 병리(정상/손상 비교, 동작 있으면 동작) → 증상 연결 → 치료(하위 버튼 2~4개). 사용자가 확정해야 다음으로.
2. **에셋 목록·출처 확정** — 표로 정리: 구조물 / 출처(Z-Anatomy 또는 절차적 생성) / 비고. 정밀도가 중요한 구조(주인공 인대·힘줄)는 뼈 랜드마크 + 문헌 부착부로 직접 생성.
3. **추출·피부 생성** — `*_a.py`. 구조 확인 뷰어 전달 → 사용자 검토.
4. **핵심 구조 생성·리그** — `*_b.py`. 부착부·관절축·스키닝 가중치 export → 검토 뷰어.
5. **뷰어** — 5단계 스크립트·동작·병리·치료 연출. 사용자 피드백 반복 후 사이트 팩으로 등록·배포.

## 3. 기술 스택 (변경 금지 사항 포함)
- Blender **bpy 파이썬 모듈**(pip `bpy`, venv `/home/claude/bl`) 헤드리스. Z-Anatomy `Startup.blend`(CC BY-SA 4.0, BodyParts3D 파생)에서 추출. 새 세션마다 Z-Anatomy를 다시 내려받아야 한다(GitHub `Z-Anatomy/Z-Anatomy` 저장소, 파일 수 GB — `git clone --depth 1`).
- 산출물: 구조물별 `{name, layer, verts, tris, ao, w, morphs}` JSON → 뷰어 HTML에 `__DATA__`로 인라인. glb는 보조.
- 뷰어: Three.js r128(cdnjs), 단일 HTML. 공통 뷰어 엔진(`common/viewer.js`)으로 통합하는 작업이 다음 과제.
- 사이트: 빌드 도구 없는 순수 HTML. GitHub `drseokee/drfirstbutton-web` (public) → Cloudflare Worker `drfirstbutton-web` 자동 배포(https://drfirstbutton-web.kneps.workers.dev). Claude는 사용자가 발급한 저장소 한정 토큰으로 push 한다(토큰은 저장하지 않으므로 세션마다 다시 받는다).

## 4. 네이밍·좌표 규칙 (CONVENTIONS)
- 오브젝트 이름 `층__구조[__변형]`: 층 = `bone | tendon | lig | nerve | vessel | muscle | skin | prop`. 변형 접미사 `__cut`(단면 세트) 등. 예: `lig__atfl`, `tendon__fdp3__cut`, `bone__pp3`.
- 좌표계: 팩마다 관절 중심을 원점으로 한 해부 좌표(미터). Z-Anatomy 원본: 오른쪽 = -x, 앞 = -y, 위 = +z. 뷰어에서 화면 좌표로 바꾸는 매핑은 팩별로 정의(손: pos=[-x,-z,-y] / 발: pos=[-y, z, -x] 앞=+X, 위=+Y, 바깥=+Z).
- 색: bone #dccfb4(따뜻한 상아색, 새하얗게 두지 말 것), nerve #f2c94c, lig #a9bfd6(주인공 인대는 #4f86e0 계열), tendon #f4efe2, muscle #a04a48, skin #d9a58f, 정맥 #3f5fa8, 동맥 #b03a3a.

## 5. 품질 규칙 (반드시 지킬 것)
- **관통 검사 게이트**: 구조물 쌍 메시 교차(BVH overlap) 검사를 통과한 결과물만 전달. Z-Anatomy 내부 겹침(뼈끼리, 근육)과 의도된 접촉(인대의 뼈 부착부 등)만 제외. 실패하면 배치 규칙을 고친다. (`qa.py`)
- **단면 슬라이스 검수**: 터널·통로가 있는 주제는 여러 레벨 단면 렌더로 자체 확인 후 전달.
- **렌더 스타일**: per-vertex AO 베이크(`bake_ao.py`, 광선 20개·3.5cm) + 가장자리(Fresnel) 음영 1.6~1.9 + 오브젝트별 미세 색조. 윤곽선은 기본 off. 뼈가 하얗게 뭉개지면 안 된다.
- **피부**: 뼈·근육·힘줄·인대·신경·혈관 합집합 → 피하지방식 closing(7mm 팽창 → 3.5mm 침식) → 손·발가락 사이 슬랩 절단(신경은 자기 손가락 쪽으로 밀어 넣기) → 얇은 구조물은 피부 안으로 tuck. 구조물은 피부 절단면보다 4mm(가는 관은 12mm) 아래에서 끊는다. 겉에서 보면 사람 손·발 같아야 한다.
- **동작**: 뼈는 관절 축 리그, 연부조직은 **가장 가까운 뼈 무리** 기준 스키닝(관절 근처만 혼합). 인대·힘줄은 두 뼈 사이에서 **매 프레임 다시 그리는 밴드/튜브**(길이 보존·활주·팽팽함·뼈 표면 감싸기 광선 검사). 힘줄은 도르래(pulley) 정거장 방식(관절 5.5mm 안쪽은 정거장 없음).
- **Three.js 주의**: 재료의 `onBeforeCompile`은 함수 텍스트로 캐시되므로 변형마다 `customProgramCacheKey`를 다르게 줄 것. 애니메이션 루프 첫 프레임 dt NaN 방지.
- **법적 고지**: 모든 페이지에 교육용 고지 + "Z-Anatomy (CC BY-SA 4.0) · BodyParts3D (CC BY-SA 2.1 JP)" 표시. 병원명 없음. 파생 데이터는 같은 조건으로 공개.

## 6. 뷰어 공통 UI (손목·발목에서 확정)
- 하단 단계 바(1~5), 하위 버튼 바, 캡션. Space/PageDown 다음, PageUp 이전, 숫자 1~5, R 원래 시점.
- 단계 전환 시 **카메라 유지**(첫 로드에만 시점 설정).
- 마우스: 드래그 회전, 우클릭·가운데·Shift+드래그 이동, 휠 확대, Ctrl+드래그 확대, Alt+드래그 기울이기, 더블클릭 중심 이동. 방향키 회전, Shift+방향키 이동.
- 층 토글(피부·근육·힘줄·인대·신경·혈관·뼈), 피부 투명도 슬라이더, 음영 강도, 좌우 반전(손목).
- 병리·치료 연출은 "상태 값(state) → 매 프레임 보간(anim)" 패턴. 하위 버튼·단계를 옮기면 소품(주사기·봉합사·앵커 등)은 반드시 사라져야 한다.

```
  common/style.css · site.js · data.js(이름·소개·링크·질환 목록) · hero-model.js

wrangler.jsonc        Cloudflare: assets.directory = ./site

```

## 9. 새 질환을 시작할 때 체크리스트
1. GitHub 저장소 `pipeline/`에서 `zana.py`, `bake_ao.py`, `qa.py`, 최근 팩의 `*_a.py/_b.py`, 뷰어 템플릿을 내려받는다(raw.githubusercontent.com). Z-Anatomy를 clone하고 `bpy` venv를 만든다.
2. 스테이지 스크립트(5단계) 제안 → 사용자 확정.
3. 에셋 표 → 확정. Z-Anatomy 이름 탐색(`.r` 접미사 = 오른쪽, 곡선 객체는 점별 radius 배율을 1로 정규화 후 실제 지름 지정).
4. 추출 → 피부 → AO → 구조 확인 뷰어(관통 검사 통과본만).
5. 핵심 구조 생성·리그 → 검토.
6. 뷰어 5단계 → 피드백 반복.
7. 사이트 팩 등록(`diseases/<id>/`), `data.js`에 한 줄, 관통 검사 통과 확인, push → 자동 배포 → 주소 확인.
